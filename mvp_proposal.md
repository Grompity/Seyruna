## B. THE MVP USER JOURNEY — "what does a real human actually do"

**One question. One answer. One inspect. No memory between runs — that
absence IS the experiment.**

1. A person types a real question. Optionally one line of their own
   context (the facts-field, now the SEEKER's to fill).
2. **The kind of question is determined** — already built (stage 1;
   *"the mode never self-licenses"*).
3. **Records assemble** — already built (stage 2; the shown set, capped,
   STOP-filtered, score-ordered).
4. **Synthesis speaks** — already built (stage 4; the mouth RECEIVES the
   receipt — claim, rank, kind-when-present, edges-when-present — and
   speaks from it; the product lane runs the retrieval shape: no
   hand-picked packet).
5. **Boundaries hold in the words** — already built (guards, check,
   audit, ONE bounded repair): contradiction kept, NON-DECISION kept,
   level kept, source kept distinct from the mouth's own bridge.
6. **The person can inspect WHY the answer says what it says** — NEW,
   and small: one humanized rendering of the existing trace (the why-
   lane: the shown records, each sentence's cites + lineage, what the
   guards observed, what the repair did). No new truth; one window.
7. **The person leaves with something usable** — already spoken by the
   mouth's own habits: a distinction (*"the heat of the word isn't the
   shape of the doing"*), a picture owned (*"offered as a picture"*),
   an open question held (*"That's not a failure"*). The takeaway is
   the SPEECH, not a feature.
8. **No dependency, falsifiably** — the constitution's own audit form:
   *"measured in months, healthy use shrinks"* (I.4/P6). For the MVP:
   the five questions run ONCE each; the answer must stand outside
   Ascended — a seeker could copy the sentence and lose the app.

## C. THE MVP ARCHITECTURE — the validated spine AS the product

The friend's arrow-chain (INTENT → … → TRACE) is not a target design;
it is an **inventory** — stages.py's stages 1–9 plus the trace dict,
already end-to-end, already green. The MVP adds plumbing, not parts:

- **What is new**: (1) a door — one route wrapping `run_pipeline`;
  (2) a window — the why-lane rendering of the trace. Two functions.
  No stage added, no state added, no law added.
- **The boundary is untouched by the door**: the response satisfies
  `cited ⊆ retrieved` exactly as it does in the harness; the why-lane
  re-witnesses the same boundary at product level (every cite printed
  there is in the shown set — one frozen witness, ordered by the
  product, not by taste).
- **The two-mouth cut is kept**: the speech is deterministic (compose);
  the voice is the mouth at stage 4; the UI never re-narrates.
- **The trace votes nothing**: it follows the verdict (the standing
  protocol), which is why the why-lane is an INSPECT, not a gate.
- **What the MVP does NOT do**: no packet chosen by the user (that stays
  an instrument); no session (no Soul Log to hold); no accounts; no
  queue (synchronous, one at a time).

## F. THE MINIMUM INTERFACE — defined by the loop's needs, not by taste

- **Input**: one box for the question; one smaller box for the seeker's
  own context line. That is all.
- **Response**: the mouth's words verbatim, cite-brackets as spoken —
  verbatim always (the answer's authority is the words themselves; the
  UI may never re-render the speech).
- **Evidence visibility**: the shown records, claim + level + kind when
  present (absent = silence, K2's law), edges when present — the same
  bytes the mouth received.
- **Uncertainty visibility**: present AS SPOKEN — the *"I'm not
  saying…"* register, the open-question holding, the no-bridge. No
  meters; no badges.
- **Provenance visibility**: the cites, in the answer and in the why-
  lane — and the lineage label (SOURCE / SYNTHESIS / UNSOURCED) in the
  why-lane alone.
- **Trace visibility**: the why-lane fold — open by request, not by
  default (the trace votes nothing, so it does not front the verdict).
- **Recovery/fallback**: the empty lane prints its lawful exit verbatim
  (the no-laundered nothing); the blip lane already prints the plain
  fallback; **the live mouth's empty-lane voice is UNTESTED — its first
  sighting is product traffic, not a test** (J.1).
- **The UI's one law**: it may DISPLAY the law's outputs; it may add no
  claim — no rank, no gauge, no soul, no Gate.

## I. THE SMALLEST IMPLEMENTATION SEQUENCE (boring first)

1. **Open the phase (record act)** — the letter executed; the freeze
   ledger unchanged. *Test:* the record exists. *Ugly allowed:* prose.
2. **The door** — one route on server.py's existing Handler (or the
   smallest sibling): POST {question, facts?} → {response, why, trace};
   synchronous, single. *Uses:* stages.run_pipeline, config keys.
   *New:* the route + its JSON glue. *Test:* one curl, one wet run.
   *Hardcoded:* nothing but the model's own endpoint. *Ugly:* blocking.
   *Not compromised:* the response arrives verbatim.
3. **The window (the why-lane renderer)** — one function:
   trace → {shown records; per-sentence cites+lineage; observations;
   repairs; the exit when taken}. *Test:* offline, injected traces;
   the new boundary-witness above. *Hardcoded:* the rendering itself.
   *Ugly:* a <pre>-grade presentation is fine. *Not compromised:* it
   renders the trace; it votes nothing.
4. **The page** — the existing shell: one box, one line, the answer, one
   fold. *Test:* three human runs (wet, out-of-shelf, one of the five).
   *Ugly:* every pixel; the aesthetic is NOT this phase.
5. **The five traffic** — C1–C5 through the door, FAIL-IF verdicts
   (First Seeker seat), trace after; results added to five-visible as
   a NEW section — *the originals are not overwritten: the file's own
   header forbids it.*
6. **The empty-lane sighting** — the out-of-shelf probe's answer read on
   the ladder (MODEL-QUALITY likely; MACHINERY possible; anything
   constitutional = a finding to be preserved whole, not a patch to be
   guessed).

*Everything unneeded stays hardcoded: the shelf (a static file), the
mouth (one model), the cap (four), the kind-lexicon (the rule-pack).*
